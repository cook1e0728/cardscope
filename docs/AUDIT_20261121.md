## 二、複合特徵搜尋引擎優化

### 1. 使用者痛點與 7 大根因
使用者輸入 `30th皮卡丘`、`30周年皮卡丘`、`30週年皮卡丘`、`皮卡丘30th`、`皮卡丘 30周年`、`151皮卡丘`、`M6a皮卡丘` 等「系列／周年＋卡名／卡號＋稀有度＋版本」複合條件時，原搜尋鏈路會回傳 0 筆，經盤點有 7 大根因：
1. **無空白中英數邊界未切詞**：原 `providers/search-query.mjs` 僅特例拆離字尾稀有度代碼（如 `阿爾宙斯UR`），未切分系列／周年與卡名邊界；帶空白時因不認系列詞又重新黏回單一卡名。
2. **周年同義詞僅接受整串精準符合且漏寫法**：原 `server.mjs` 的 `anniversaryTerms` 採 `^...$` 錨定正則，複合查詢直接回空陣列，且缺 `周年記念`／`週年紀念`／`30th celebration`／`me55`／`1st/2nd/3rd` 等跨語別名。
3. **SQL 三段互斥 Fallback 無跨表交集**：原 `search_cards_ranked` 的 `name_matched` → `text_matched` → `series_hit` 嚴格互斥，且 `p_patterns` 為 OR 聯集，無法表達「指定系列集合 AND 卡片名稱／卡號特徵」。
4. **次要重試與本地備援全失效**：`search_fold_names` 與 `search_name_suggestion` 僅查無系列資訊的 `tcg_cards.search_names`；本地 `data/catalog.json` 備援僅做單字串 `includes`，不支援跨欄位 AND。
5. **跨語卡名別名無法作用於複合詞片段**：`externalAliasIndex` 原先僅比對整串原始輸入，無法對拆解後的卡名片段展開（如 `皮卡丘` → `Pikachu`）。
6. **即時建議與前端缺系列條件回饋**：`fields=suggest` 直接承接 0 結果；建議列與已套用條件 chip 未呈現／不支援移除系列條件；`series-band.js` 依賴 `meta.queryTerms` 導致上方系列分頁歸零。
7. **系列查詢截斷風險**：原 `series_hit`（`limit 5`）與 `series_matched`（`limit 100`）會截斷跨地區多彈周年系列（如 30 周年跨 JP/TW `M6a`、`MF`、US `me55`/`me55c`）與超過 100 張的彈數。

### 2. 架構變更（Catalog-Driven 特徵拆解 ＋ SQL 7 參數交集，零新增索引、0 MB 儲存增量）
- **純函式核心（`providers/search-query.mjs`）**：統一維護 `chineseNumber`、`toChineseNumber`、`ordinalEn`、`anniversaryTerms`（含跨語別名如 `30th celebration`/`me55`、`cel25`/`quarter century`）、`buildSeriesIndex(series)`（以 `catalog.series` 動態建索引，排除卡名後綴與泛用包裝詞）與複合特徵解析器 `parseSearchQuery(raw, { seriesIndex, region })`。
- **後端查詢串接（`server.mjs`）**：
  - 以 `WeakMap` 快取 `getSeriesSearchIndex(catalog)`，`/api/search` 先讀取暖快取建立系列索引再做複合拆解；周年詞無對應系列時不誤剝詞。
  - `searchCatalogDatabase`／`searchCatalogDatabaseIn` 依 `dbForId` 分流主庫與 `ip2`（如 30th 全屬主庫則跳過 `ip2`、UA 系列跳過主庫）；優先呼叫 7 參數 `search_cards_ranked(..., p_series_ids)`（`p_series_ids` 上限 50、`p_patterns` 上限 12）；若資料庫尚未套用 migration 而回 `PGRST202`/`404`，自動降級至有限度 PostgREST `tcg_printings` → `tcg_cards` 交集，並啟用 5 分鐘斷路器 `rankedSeriesMissingUntil`。
  - 依命中 `seriesIds` 過濾 card printings（讓縮圖與卡號精準顯示目標系列，其餘同 canonical 圖片保留於 `fallbackImageUrls`）。
  - 零結果三段防線：(1) 保留 `seriesIds` 重試 `foldedNameSpans`；(2) 防誤拆安全網以未拆系列原查詢補查，命中時自動清除 `meta.parsed.series`；(3) 帶 `allSeriesIds` 偵測跨區 `otherRegion` 提示，並於去掉系列後命中時回傳 `suggestion.reason = 'name-only-series'`。
  - 本地 `catalog.json` 備援同步支援跨欄位 `seriesIds` AND 卡名／卡號比對，回應補充 `meta.parsed.series` 與 `meta.seriesTerms`。
- **前端互動與回饋（`index.html`、`ui-enhancements.js`、`series-band.js`）**：已套用篩選 chip 支援顯示並一鍵移除系列條件；即時建議頂列顯示系列／稀有度／版本 chip，卡片副標帶入系列代碼；上方系列列整合 `meta.seriesTerms`。

## 三、前後端資安強化（6 大項）

針對只讀資安盤點所列出的 High / Medium / Low 風險，共落實 6 大項防禦強化（涵蓋 `server.mjs`、`providers/backend-reliability.mjs`、`providers/graded-prices.mjs`、`test/backend-reliability.test.mjs`、`test/server-hardening.test.mjs`）：

1. **Rate Limiter OOM 防護與 `ORIGIN_VERIFY_SECRET` 來源驗證（High）**：
   - `createRateLimiter` 補上追蹤鍵上限（預設 `10,000` 筆）：滿載時優先清理過期鍵，仍滿則淘汰最舊鍵，阻斷以隨機偽造 IP 撐爆 512 MB 執行個體記憶體的 OOM 攻擊。
   - 新增可選環境變數 `ORIGIN_VERIFY_SECRET`：設定後僅於請求標頭 `X-Origin-Verify` 通過 `crypto.timingSafeEqual` 驗證時才採信 `CF-Connecting-IP`，否則退回 `req.socket?.remoteAddress`（未設定時維持向後相容），`rateLimited()` 與 `clientIp()` 共用同一判定。
2. **公開健康與覆蓋率端點錯誤脫敏（Medium）**：
   - `createBoundedSnapshotCache`（`providers/backend-reliability.mjs`）在重整失敗回傳 stale 快取時，原始錯誤僅寫入 `console.error`，對外 `cache.error` 統一改為固定代碼 `'UPSTREAM_UNAVAILABLE'`。
   - `loadCatalogHealth()`（`server.mjs`）在 v2 RPC 降級時僅記錄 `console.error`，對外 `healthCompatibilityWarning` 固定回傳 `'v2 snapshot unavailable'`，不再洩漏 PostgREST／Supabase 原始錯誤字串。
3. **SEO 資料庫查詢入口限流與 ID 白名單（Medium）**：
   - 新增 `seoLimiter`（`SEO_RATE_LIMIT_PER_MINUTE`，預設 `60` 次/分），保護帶 `?card=` 或 `?series=` 的 `/` 查詢（純首頁 `/` 不受限流）。
   - `seoRequestTarget` 驗證 ID 格式白名單 `/^[\w:.\-/]{1,128}$/`，不合法 ID 直接跳過查庫且不寫入 `seoCache`。
4. **低配額外部價格端點 per-IP 限流與併發去重（Medium）**：
   - `/api/graded-prices`（`GRADED_RATE_LIMIT_PER_MINUTE`，預設 `15`）與 `/api/ebay-listings`（`EBAY_RATE_LIMIT_PER_MINUTE`，預設 `15`）各設專屬 per-IP 限流器，防止單一來源耗盡全站每日外部配額。
   - `createGradedPrices`（`providers/graded-prices.mjs`）補上 `pending` Map 進行 in-flight 併發去重，同時段相同卡查詢只消耗一次每日配額並於 `finally` 清除。
5. **`/api/sync/*` 預驗證與 body 上限收斂（Medium）**：
   - `pull`／`delete` 請求體上限收斂為 `1,024` bytes（`readJsonBody(req, 1024)`）。
   - Google 登入 `push` 遇大於 4 KB 或未知長度（chunked）payload 時，先驗證 `googleSyncKey(token)` 才讀入 2 MB body；小型 payload 亦於頂層鍵檢查後、萬筆驗證迴圈前先行驗 token，防止未授權 2 MB JSON CPU／記憶體放大攻擊。
6. **參數白名單、PostgREST 跳脫、圖片代理收緊與 OAuth `code` 遮罩（Low–Medium）**：
   - `/api/search` 驗 `region` 白名單（非法回 400）；`/api/reports` 驗 `cardId ≤ 128`、`cardName ≤ 100`（禁控制字元）、`game` 白名單、`limit` 夾緊 `[1, 100]` 並限制 `statsParams` `limit=1000`；`/api/cards` 驗 `series ≤ 128`；`/api/cards/:id`（含 `/market`、`/price-history`）驗 ID 長度與控制字元；`loadCardFromDatabaseIn` 備援 `or=(...)`/`in.(...)` 剔除 `"` 與 `\`。
   - `onePieceImageTarget` 拒絕含 `port`／`username`／`password` 的目標；`proxyOnePieceImage` 改採點陣圖 MIME 白名單（`image/png`、`image/jpeg`、`image/webp`、`image/avif`、`image/gif`，排除 `image/svg+xml`）並以 `readBoundedResponse` 串流讀取，超過 5 MB 立即中止。
   - `inflightKey` 透過 `redactInflightSearch` 遮罩 query string 中的 `code=` OAuth 授權碼參數值。

> **後續可評估項目**：`localStorage` 儲存 Google 登入憑證與同步碼屬於防禦縱深議題（目前全站具嚴格 SHA-256 CSP 與完整 DOM 跳脫、無 XSS），長期可評估改為 `HttpOnly; Secure; SameSite=Lax` Session Cookie；另建議於 Render／Cloudflare 端設定 `ORIGIN_VERIFY_SECRET` 並搭配 `X-Origin-Verify` 規則鎖定源站直連。

## 四、雙裝置互動 E2E 體檢發現與收尾修復

以 Playwright 在獨立啟動之 `server.mjs` 上執行雙裝置（桌機 `1440×900` ＋ 手機 `375×812`）6 大主流程端對端互動稽核（`e2e-full-audit.mjs`），共檢出並即時修復以下 3 項真實缺陷：

1. **搜尋即時建議按 `Escape` 競態重開（`ui-enhancements.js`、`test/search-suggest.test.mjs`）**：
   - **現象**：在 150ms debounce 尚未觸發或請求仍在飛行中時按 `Escape`，原本僅在 `!list.hidden` 時呼叫 `close()` 而未清 `timer`／未 `abort()`，導致建議清單 350ms 後重新彈出（`reopenedAfterFastEsc: true`）。
   - **修復**：於 `installSearchSuggest` 處理 `event.key === 'Escape'` 時，不論清單是否已開啟皆固定執行 `clearTimeout(timer); controller?.abort();`，再於 `!list.hidden` 時執行 `preventDefault()`、`stopPropagation()` 與 `close()`；並新增回歸測試至 `test/search-suggest.test.mjs`。
2. **離線備援航海王樣本卡圖違反 CSP `img-src`（`data/catalog.json`）**：
   - **現象**：`data/catalog.json` 中 `onepiece-luffy-op05-119-jp` 仍指向舊第三方網域 `https://optcg-api.arjunbansal-ai.workers.dev/images/OP05-119`，不在 CSP `img-src` 白名單內，觸發 5–6 筆瀏覽器 CSP 違規錯誤。
   - **修復**：改為官方白名單圖源 `https://asia-en.onepiece-cardgame.com/images/cardlist/card/OP05-119.png`（`imageSource: "onepiece-official"`），前端自動走同源代理 `/api/images/onepiece?url=...`（實測 HTTP 200 `image/png`），CSP 違規降至 0 筆且保留 `test/catalog.test.mjs` 的 `card.imageUrl` 契約。
3. **`/?game=union-arena` 無第二庫設定時回傳誤導性 400（`server.mjs`、`test/second-db.test.mjs`）**：
   - **現象**：未設定 `SUPABASE2_*` 時 `GET /api/cards?game=union-arena` 回傳 HTTP 400 與「`請選擇單一卡牌遊戲`」，對使用者造成誤解。
   - **修復**：`server.mjs` 對 `SECOND_DB_GAMES` 已知遊戲於 `!secondDbConfigured()` 時改回 **HTTP 503** 與清楚文案「`此遊戲資料暫時無法連線`」（未知遊戲 ID 仍維持回傳 HTTP 400）；同步更新 `test/second-db.test.mjs`。
