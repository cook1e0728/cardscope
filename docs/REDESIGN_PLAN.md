# CardScope 整體重新設計計畫書

狀態：**已拍板**（2026-11-12 使用者「照建議開始」：第 5 節決定 3–11 全照建議，見 ADR 0056）
起草：Fable 5.2（設計主導）　日期：2026-11-11
拍板後：Opus 主導執行、Sonnet 派工實作；本文件是唯一依據。

不變的前提見 `docs/PRODUCT_PLAN.md`：產品定位、資料與價格的誠實原則、資訊架構 `IP → 語言／地區 → 世代或分類 → 系列／產品 → 卡片`、WCAG 2.2 AA、操作區 44×44px、不花錢、純 HTML/CSS/JS 不加框架、CSP 規則。本計畫只改「長相、版面骨架、操作方式、資訊多寡」，不改資料與 API 的意義。

## 1. 為什麼要重做

目前的畫面是一輪一輪疊上去的（卡冊風格、夜空首頁、詳細視窗面板、特效），每一輪各自合理，合起來有五個問題：

1. **同一件事有好幾個入口。** 「只看我的收藏」「只看缺的卡」是兩顆分開的按鈕；卡片上有星號又有數量加減。
2. **說明文字太多。** 漲跌榜標題下有三行說明與警語；卡牆上方、詳細視窗裡都有寫給開發者看的規則句。
3. **框線與底色沒有規則。** 米色有五、六階，有東西就加框。
4. **按鈕不好看。** 頂欄的紅色搜尋鈕顏色太重、搜尋／圖鑑／我的收藏三顆鈕的質感不夠好；全站按鈕沒有統一的樣子（使用者 2026-11-11 指出）。
5. **骨架不一致。** 首頁是深色大搜尋區，遊戲頁是工具列加卡牆，詳細資料是彈出視窗，收藏是另一種版面；換頁像換了一個網站。

使用者 2026-11-11 在預覽上圈出四處：頂欄（紅色搜尋鈕與三顆導覽鈕）、兩顆「只看…」按鈕、卡圖上的星號、漲跌榜標題與說明。其中頂欄經使用者更正：**三顆導覽鈕是好的、要保留**，問題是紅色搜尋鈕的顏色與三顆鈕的質感，不是入口重複（第 4 類）。其餘三處屬於第 1、2 類，尚待使用者確認。

## 2. 方向選項（要拍板的第一件事）

> **使用者定調（2026-11-11）：**「我想保留兔子形象，這是一種特色象徵；酷炫的卡牌展示，吸引視覺又能當實用的查卡工具。」
> 據此，A、B 之外多一個合併的方向 **B′：展示首頁＋卡冊內頁**（見本節末），目前的預覽（`?dir=b`）已改成 B′。


三個骨架。差別在「使用者一進來先做什麼」。

### A. 查卡工具（搜尋優先）
- 頂欄維持 Logo、搜尋框、搜尋／圖鑑／我的收藏三顆導覽鈕，只重做按鈕的樣子。
- 首頁就是搜尋框、最近看過、各遊戲入口，沒有大橫幅。
- 結果與卡牆是同一個版面；詳細資料仍是彈出視窗。
- 適合：來查一張卡就走的人。三個方向裡改動最小，但不算小：第 4 節的頂欄、工具列、卡片、收藏合併都還是要做。
- 缺點：逛系列、集卡這條路變弱；「跨版本對照」沒有被凸顯。

### B. 卡冊（瀏覽與收藏優先）— **建議**
- 桌機三欄：左邊固定側欄（遊戲 → 版本 → 系列，可收合），中間卡牆，右邊是卡片詳細資料的側板（點卡不跳視窗，卡牆還看得到，可用方向鍵連續看下一張）。
- 手機：側欄變成從底部拉起的選單，詳細資料是全螢幕的一頁，可左右滑換卡。
- 搜尋框永遠在頂欄正中，搜尋結果也顯示在同一個卡牆裡。
- 首頁用同一個骨架：側欄在左，中間是各遊戲入口與最新系列（不是把所有遊戲的卡混成一面牆：目前程式與 PRODUCT_PLAN 都規定卡片要先選遊戲才列出，這點不改）。
- 適合：逛系列、比版本、集卡。最符合產品定位「查證與收藏探索入口」。
- 缺點：工作量最大（側欄、側板是新的版面骨架）；首頁的夜空主視覺要縮成一條或拿掉。
- 寬度：桌機 1440px 扣掉側欄約 220px（可收合）與側板約 420px 後，卡牆從一排 6 張變成 4 張；側板關著時回到 6 張。

### C. 行情看板（價格優先）
- 首頁以漲跌榜、時事、收藏總值為主，卡牆退到第二層。
- 適合：追價格的人。
- 缺點：與 PRODUCT_PLAN「資料正確性、中文導覽與搜尋優先於價格功能」衝突；目前只有歐洲參考價，撐不起一個看板。**不建議**，列出來是為了說明為什麼不選。

### B′. 展示首頁＋卡冊內頁 — **已定（使用者 2026-11-11：「定 B′」）**
- **首頁是門面**：保留夜空、持劍兔卡與卡牌展示、大搜尋框，滿版，不放側欄。這裡負責「吸引視覺」。
- **遊戲頁、搜尋結果、收藏是工具**：用方向 B 的骨架（左側欄選遊戲／版本／系列，中間卡牆，右側展開詳細資料）。這裡負責「實用」。
- **兔子是貫穿全站的象徵**，不只在首頁：頂欄 Logo、空白狀態（沒有結果、還沒收藏）、載入中、錯誤頁、示範影片片尾、分享圖。內頁用小的、安靜的版本，不搶卡片。
- **酷炫的卡牌展示**集中在三處：首頁的展示卡（可換成當期高稀有度卡、可傾斜、有全息光）、詳細資料裡的卡圖（放大、傾斜、全息光）、延後的開包特效。卡牆本身保持安靜，方便查。
- 與 PRODUCT_PLAN 的關係：沿用 ADR 0048／0050／0051 的首頁主視覺，不推翻；金屬與全息質感仍只用在 CardScope 自己的框與展示卡上，不在一般卡圖上製造假閃卡。

**建議 B′（原建議 B）。** 理由：六個遊戲、多版本、要集卡，這是「翻冊子」的操作，不是「查一筆」的操作；側欄把現在分散在頂欄、頻道列、版本下拉、系列橫幅的四層選擇收成一個固定位置；側板讓看卡與翻卡不互相打斷，也順便解掉開卡等待骨架的問題（先顯示卡牆已有的資料）。若想先求快，可以先做 A，A 的頂欄與卡牆在 B 裡都留得下來。

## 3. 全站設計規則（不論選哪個方向都適用）

| 項目 | 規則 |
|---|---|
| 底色 | 只有三層：頁面 `#F8F5EE`、內容面 `#FFFFFF`、凹陷區 `#EFEAE0`（輸入框、分段按鈕的底）。深紫只用在頂欄。 |
| 框線 | 同一層只用一種區分方式（白底，或 1px `#E7E1D4`），不重複。只有可點、可輸入的東西有框。 |
| 遊戲色 | 只出現在小處：選中狀態的字與細線、遊戲標籤。不整塊塗滿。新品紅 `--new` 維持獨立。 |
| 字 | 四級：標題 20–28px、內文 15–16px、次要 13px、標註 12px。數字一律等寬數字。 |
| 文字量 | 介面上不解釋規則。必要的來源與警語收進一個「ⓘ」按鈕，點開才看；法律與誠實原則要求的那一句（例如「不是成交價」）留一句短的。 |
| 一件事一個入口 | 收藏只有一個動作；篩選只有一組。（頂欄的搜尋框與三顆導覽鈕不算重複，保留。） |
| 按鈕 | 全站只有三種：主要（一頁最多一顆，實心）、次要（白底細框）、文字鈕。同一種在哪一頁都長一樣：同樣的圓角、高度 44px、按下與滑過的回饋。質感用「紙感」（決定 2，已定）。 |
| 手感 | 可以按的東西按下去都縮到 97%（`transform:scale(.97)`），100–160ms；轉場只寫要變的屬性，不用 `transition:all`；用自訂緩出曲線 `cubic-bezier(.23,1,.32,1)`，不用 ease-in；介面動畫不超過 300ms；滑過效果一律包在 `@media (hover:hover) and (pointer:fine)`；用鍵盤觸發的動作不加動畫。 |
| 陰影與層次 | 陰影帶暖色（`rgba(60,45,20,…)`）、很淡，不用純黑；需要「放在凹槽裡」的元件（搜尋框、分段按鈕）用兩層：外層凹陷底、內層白色內容面，內外圓角同心。不用 1px 純灰實線當唯一的區分手段。 |
| 動態 | 沿用 ADR 0047 的上限與「暫停動態」開關；特效（look-effects）保留，但新骨架完成前不加新的。 |

## 5. 需要使用者決定的事

1. **方向：已定 B′**（展示首頁＋卡冊內頁，使用者 2026-11-11 看過預覽後決定）。 兩個方向 2026-11-11 已做本機預覽給使用者（`look-next.css`＋`look-next.js`，網址加 `?dir=a` 或 `?dir=b`，`?dir=off` 關掉）。預覽的 B 只有桌機 1000px 以上：側欄是把既有的遊戲列、版本選單、系列橫幅搬過去換排法，側板是把詳細視窗靠右；手機版、鍵盤焦點、上一頁、方向鍵都還是舊行為，不能當成品。
2. **按鈕的質感：已定為「紙感」**（使用者 2026-11-11 從平面／紙感／深色頂欄三版預覽中選定）。白色紙片配很淡的暖色陰影，不加實線框；搜尋框放在凹陷底裡、內層是白色；搜尋鈕白底配遊戲色放大鏡，不再整塊正紅；目前所在頁＝粗體加 1.5px 墨色細框（不只靠顏色）；頂欄底下的紅線改成淡色細線。樣式在本機 `look-next.css` 的「頂欄按鈕：紙感」區塊，目前只做了 761px 以上；手機頂欄與全站其他按鈕照同一套質感做，屬階段 1。
3. **卡圖上的星號：** (a) 固定顯示在卡圖右上角；(b) 桌機滑過才出現、手機固定；(c) 不放在卡圖上，放在卡名那一行右邊。（建議 c：不遮卡圖，位置固定，手機桌機一致）
4. **漲跌榜與時事放哪？** 首頁下方、獨立的「行情」頁，或側欄下方的小區塊。（建議獨立頁，頂欄維持三顆鈕不加第四顆，從首頁與收藏頁連過去）
5. **詳細資料不分頁（資訊與價格連續排）可以嗎？**（建議可以；價格區塊標題固定在側板頂端可跳過去）
6. **手機一排幾張卡？** 現在 4 張，卡名只放得下三四個字。3 張時每張約 106px 寬，若星號與卡名同一行（決定 3 的 c）卡名還是只有四個字左右；2 張才真的寬鬆。（建議 3 張，星號在手機改放卡號那一行右邊）
7. **我的收藏的進階功能留在哪？**（品況、閃卡版本、備註、備份匯出入、CSV、各系列進度）(a) 收藏頁用卡牆版面，進階功能收進每張卡的側板與一個「管理」選單；(b) 維持現在的對話框，只換樣式。（建議 a，但它是階段 5 裡最大的一塊）
8. **實體商品分類放哪？** 側欄的系列底下多一層「商品」，或維持在卡牆上方。（建議放進側欄）
9. **手機專用元件留哪些？** 底部導覽列、2×5 快速探索格、拇指稀有度快選盤。（建議留底部導覽列，另外兩個由底部拉起的側欄選單與工具列取代）
10. **收藏後怎麼改張數、怎麼取消？** 卡片上已收藏時顯示「− 數量 ＋」，減到 0 就是取消（有品況或備註時才跳確認）；還是張數只能進側板改。（建議前者）
11. **圈起來的另外三處，我的理解對嗎？**（頂欄已更正）兩顆「只看…」＝該合成一組；星號＝位置與樣式要重想；漲跌榜＝說明太多。若是別的意思請指出。
12. **首頁的夜空兔子主視覺：已定，保留整塊**（使用者 2026-11-11：兔子是特色象徵，要有酷炫的卡牌展示）。首頁滿版展示、不放側欄；兔子另外延伸到空白狀態、載入、錯誤頁（見方向 B′）。

## 6. 執行方式（拍板後才生效）

**分工：** Opus 主導（拆工作包、審 diff、整合、驗收）；Sonnet 實作工作包；Fable 只在方向或審美有爭議時裁決。每個工作包的可寫檔案不重疊。這份分工只適用於本次重新設計，取代 PRODUCT_PLAN「模型分工」一節中對應的部分（那一節是 Codex 專用）。

**在哪裡做：** 開一條長期分支 `redesign-v2`，做完一個階段就 commit、push 到該分支，**不進 main**；使用者在本機預覽看過、同意後才合併上線。不做「用開關包住、新舊並存」：卡片、工具列、詳細資料的標記都寫在 JS 字串裡（`ui-enhancements.js` 的 cardMarkup、openCard 等），新舊並存等於每處寫兩套、測試也兩套。main 上的小修照常進行，每個階段開始前先把 main 併進分支。

**開工前先改文件：** 拍板後第一件事是更新 PRODUCT_PLAN 第 4、5 節（頂欄導覽、詳細頁分頁、底色與框線色值、首頁第一屏）並補一份 ADR，否則每個階段都會和現行規定與對原始碼文字比對的測試衝突。

**階段（以方向 B 為例；選 A 則做 1、3、5，不做 2、4）：**

| 階段 | 內容 | 完成的樣子 |
|---|---|---|
| 1. 減法與變數 | 按鈕統一成三種並套用選定的質感（頂欄先做）；說明句與警語收進 ⓘ；底色三層、框線、字級整理成變數 | 沒有功能消失；手機 375px 頂欄不換行；鍵盤可用 |
| 2. 外框骨架 | 側欄（遊戲→版本→系列，含商品與七龍珠超在內六個遊戲），只在遊戲頁、搜尋結果、收藏出現；首頁維持滿版展示；手機底部選單 | 網址、上一頁、分享連結行為不變 |
| 3. 卡牆與工具列 | 卡片三行、收藏單一動作、工具列一排、進度一行；混合牆才顯示版本標籤 | 六個遊戲各看一個系列與一次搜尋；收藏加入、改張數、取消都正常 |
| 4. 側板 | 詳細資料改側板；先顯示卡牆已有資料，價格後補 | 見下方「側板要解的五件事」 |
| 5. 收藏頁與行情頁 | 依決定 4、7 的結果套用同一版面 | 備份匯出入、CSV、品況與備註都還在 |
| 6. 收尾 | 刪掉用不到的舊樣式與舊元件，更新文件 | 沒有死碼；測試、桌機 1440×900、手機 375×812 都驗過；合併進 main |

**側板要解的五件事**（都有現成程式會擋，agy 審查後補上）：
1. 焦點：`dialog-focus.js` 在 `#modal.open` 時鎖住整頁的 Tab。桌機側板不能鎖（要能 Tab 回卡牆與側欄），手機全螢幕時要鎖，依寬度分流。
2. 上一頁：`navigation-state.js` 用 `#modal.open` 判斷要新增還是取代歷史，關閉時會 `history.back()`。側板開著時又在側欄換系列，Esc 會退回上一個系列而不是只關側板，狀態機要重寫這一段。
3. 方向鍵：現在 `#modal.open` 時全頁攔截左右鍵換卡。側板常駐後，在搜尋框或側欄裡按左右鍵不可以換卡。
4. 兩段顯示：`openCard` 目前等三個請求都回來才一次寫入，`index.html` 還有監聽會把「正在載入…」換成骨架；`look-effects.js` 的開卡轉場靠 0.5 秒內出現卡圖。改成先畫已有資料、價格後補時，這三處要一起改。
5. 寬度：側板開著時卡牆 4 張一排，關著 6 張，切換時不可讓使用者正在看的那張卡跳走。

**每個階段的驗收：** `node --test` 全過（改到的文字比對測試一併更新，算在工作包裡）；本機預覽桌機與手機截圖；鍵盤走一遍；「暫停動態」與減少動態下正常；更新 `docs/AGENT_BATON.md`，commit 後 push 到分支。

**其他風險：**
- `ui-enhancements.js`、`index.html` 是多數功能共用的大檔，兩個工作包不可同時寫；階段 3 與 4 要排先後。
- 分支活得久，main 的小修要常併進來，否則最後合併會很痛。
- 本機現有未提交的 `look-next.css`（與 `index.html` 載入它的那一行）是討論用的預覽稿，拍板後併入階段 1 或刪除，不直接上線。

**不在這次範圍：** 資料與 API 的意義、價格來源、登入、開包特效、新的動畫。
