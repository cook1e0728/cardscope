## 0. 限制與可信度

- 載入秒數是「無頭瀏覽器、冷快取、Render 已醒著」的粗估，真實使用者（尤其行動網路、伺服器休眠時）會更慢；只能當相對比較。
- 卡圖多為直連官方站，無頭瀏覽器載圖明顯比 App 瀏覽器慢（同一頁 8 秒後無頭只載入 5 張、App 瀏覽器約 17–24 張），所以「白框＋SAMPLE」的嚴重度請以 App 瀏覽器結果為準。
- 沒有稽核：登入／會員、後台、錯誤狀態（無法在不破壞正式站的前提下製造 5xx）、遊戲王／芙莉蓮／排球少年各自的詳細頁、螢幕閱讀器實測、對比重新量測（沿用 HANDOFF 51 的結果）。
- 流程 a 的手機版只做了「魯夫」搜尋與詳細頁；「桃歹郎ex SAR」在手機的行為與桌面相同（API 層即為零結果，見問題 1）。
- 同類網站：Limitless、PkmnCards、台灣官方、日本官方以截圖＋頁面實看為準；只看公開頁面、未登入。WebFetch 的摘要有可能是快取舊內容，未採用其中無法在截圖驗證的細節。

## 1. 主要任務流程

### 1a. 首頁找一張特定卡

| 項目 | 日版「桃歹郎ex SAR」 | 航海王「魯夫」 |
|---|---|---|
| 查詢 | `桃歹郎ex SAR`（自然語句） | `魯夫` |
| 結果 | **0 筆**，黃色提示條「找不到結果；不以示範卡片填補。」，無任何建議（`d-e1-zero-results-landing.png`） | 40 筆，第 1 筆是寶可夢「Fluffy Berry」（`d-a4-2-results.png`、`m-a4-2-results.png`） |
| 改成 `桃歹郎` | 19 筆（日／台／美版與各稀有度混排，按卡號排序），要自己找「日版 · 090 · SAR」再點開，約 3 次互動（聚焦輸入＋Enter、捲動、點卡）；詳細頁正確開在日版（`d-a3-detail-info.png`） | 見下方「瀏覽」 |
| 時間 | 搜尋 API 約 0.25–2.3 秒；從 Enter 到出現結果約 1.4–2 秒 | 同左 |

觀察：

- API `meta.searchScope`：`桃歹郎`、`桃歹郎ex` 為 `bounded-database-query`（有結果），`桃歹郎ex SAR` 變成 `loaded-catalog-only`、候選 0。也就是說「名稱＋稀有度」這種玩家最自然的查法，在搜尋端被當成一整段子字串，沒有拆解（`モモワロウex SAR` 同樣 0 筆）。
- 「三次互動內找到正確印刷版本」：用乾淨關鍵字可達成；用自然語句反而最多要重打一次（至少 +2 次互動）。
- 搜尋後頁面自動捲到卡片區（`scrollY` 約 1164 桌面／1244 手機），**結果標題「「桃歹郎」的搜尋結果（19）」被頂欄與 sticky 工具列蓋住**，桌面第一列卡片的上半被工具列蓋掉（`d-a2-2-results.png`）。
- 搜尋結果標題的數字是「上限 40」不是總數：API `candidateCount` 225、`mayHaveMore: true`，介面沒有說還有更多，也沒有「載入更多」。
- 結果依卡號排序而非相關度；跨 IP、跨版本混在同一個格子牆（同一張桃歹郎ex 的日版／台版／美版各占一格）。
- 好的地方：在遊戲頁內搜尋會限定目前版本，並提示「相關系列與商品 9 項列在上方『搜尋』分頁」「亞洲英文版 12 項」（航海王實測，符合主方案第 4 節）。

### 1b. 瀏覽：選遊戲 → 版本 → 系列 → 稀有度 → 卡片

以寶可夢日版 SV6a 為例：

| 步驟 | 互動數 | 時間（粗估） | 備註 |
|---|---|---|---|
| 點首頁「寶可夢」 | 1 | 首次約 6–9 秒，之後約 1 秒 | 版本預設日版（橫幅有 日／台／美 按鈕），所以選版本不一定要點 |
| 點系列磚「SV6a 黑夜漫遊者」 | 2 | 約 2 秒出 94 張 | 點完頁面自動捲動，橫幅被捲走 |
| 稀有度下拉選 SAR（5） | 3（下拉＋選項算 1–2 次） | 約 0.4 秒 | 下拉有 38 個選項，含此系列沒有的 MUR/FUR/BWR 等 |
| 點卡片 | 4 | 約 0.3 秒開窗 | |

結論：不篩稀有度時 3 次互動（遊戲→系列→卡），符合主方案；加稀有度是第 4–5 次。

卡住或困惑：

- 遊戲頁第一屏的系列橫幅（版本按鈕、文字分頁、方形系列磚）做得清楚（`d-b1-game-pokemon.png`），這是目前最成熟的區塊。
- 但橫幅下方的預設內容是「寶可夢卡片圖鑑：共 21,191 張」（編號低到高，從最舊的卡開始，`d-b1-game-pokemon.png`），與「最新」無關；上方舊分頁列「最新收錄／商品分類／完整圖鑑／市場資料」仍在，「最新收錄」沒有功能，另外三個只是捲動或彈資訊。
- 點系列磚後：桌面落點把系列資訊卡切掉上半（`d-b2-series-sv6a.png`）；手機橫幅被捲走，要換系列得往回捲約 540px（`m-b2-series.png`）。手機在第一張卡出現前要先經過約 1100px 的系列標題、檢視切換、篩選摘要、追蹤清單方塊與 CSV 鈕（`m-b2-series.png`）。
- 系列磚名稱用單行省略（航海王「起始牌組 黃 尤…」「補充包 神…」，`d-b4-game-onepiece.png`）；日版磚混用日文原名（M4 ニンジャスピナー）與中文名（SV6a 黑夜漫遊者）。
- 稀有度顯示不一致：同一結果混有日版代碼（RR、SAR、UR）、美版原文（Double Rare、Ultra Rare、Special Illustration Rare、Hyper Rare）、`NONE`、`Rare Holo EX`（`d-a2-2-results.png`）。`NONE` 對玩家是「卡面沒有標記」還是「資料未知」不清楚（GLOSSARY 把兩者定義為不同事物）。
- 手機篩選改為底部抽屜，運作正常（`m-b3-filter-sheet.png`）：×、套用、焦點返回都在。

### 1c. 卡片詳細頁

- 開啟方式：點卡（開窗約 0.3 秒）、永久網址 `?card=`（直接開啟約 6–12 秒才看到卡圖，無頭量測）。
- 結構：左側卡圖、中文名／原文名／卡號／稀有度四格、「分享此卡」；右側四個分頁。
  - **資訊**：只有「卡片文字：目前資料來源沒有提供…」與「收錄版本」清單。沒有系列名稱（只在清單裡有 SV6a）、沒有資料來源／更新時間／圖片狀態。台灣官方詳細頁有招式、HP、弱點、撤退（`x-pkmcard-tw-detail.jpg`），CardScope 沒有卡片文字。
  - **跨市場比價**：資訊最完整、最誠實（來源、性質、版本、原幣、觀測日、匯率、非台灣行情聲明；有走勢圖與文字摘要表，`d-c7-price-chart.png`）。問題是日版 SAR 顯示的是 Cardmarket 歐元閃卡價，並沒有說明這是哪個語言版本的行情（`d-a3-tab-跨市場比價.png`）。
  - **成交趨勢**：永遠是「目前沒有足以建立可信成交趨勢的已驗證歷史資料」；真正的走勢圖其實在「跨市場比價」分頁裡，名稱對不上。
  - **使用者回報**：只有「目前沒有使用者回報。」，DOM 中沒有任何表單或按鈕，使用者無法回報。
- 版本切換：「收錄版本」清單的每一列可點（「點擊查看此版本的卡圖」），點了網址改為該版本 `card=`、卡圖換圖（`d-c2-version-tw.png`）。外觀像資訊列而不像切換器；桌面切換後卡圖仍是空白＋SAMPLE 一段時間，手機切換時整個視窗變成全白的「正在載入…」（`m-c2-version-tw.png`）。
- 分享網址：點「分享此卡」複製網址；沒有剪貼簿權限時按鈕文字變成「請複製瀏覽器網址」（`d-c3-after-share.png`），無原生分享。`<title>` 為「桃歹郎ex SAR｜日版 SV6a 090｜CardScope」但 `canonical` 指向台版 printing（`?card=pokemon-official-tw-sv6a-090` 形式的網址），分享預覽與搜尋引擎看到的版本可能不是使用者開的那一版。
- 手機：視窗是全螢幕，先看到全寬卡圖與四個全寬資訊方塊，分頁列在視窗內約 868px 處（超過第一屏）才出現（`m-c1-modal-info.png`、`m-c6-modal-price.png`）。
- 好的地方：視窗有 `role=dialog`、焦點進關閉鈕、Esc 關閉並回到原卡、上一張／下一張、`8 / 19` 位置提示。

### 1d. 收藏

- 位置：每張卡上有「☆」收藏與「－ 0 ＋」數量；篩選工具列內有「只看收藏（N）」與「我的追蹤清單：N 張、M 件」「下載清單 CSV」（`d-d2-after-qty.png`）。
- 首頁（全部遊戲）看不到追蹤清單；頂欄的「追蹤」是不可點的 `<b>`（見問題 3）；手機底部導覽的「我的」只在遊戲頁出現，錨點到追蹤清單方塊。
- 用語不一致：星號叫「收藏」、清單叫「追蹤清單」、單位同時有「張」與「件」、CSV 叫「下載清單」；加星不會改變「0 張、0 件」，要按「＋」才算一件（兩個動作並存，沒有解釋）。
- 資料只存在本機瀏覽器（`localStorage cardscope-favorites`），畫面有說「僅儲存在此裝置」。
- 結論：能用，但「好不好找」是否定的：入口埋在篩選工具列裡，而且只有進到卡表頁才看得到。

## 2. 資訊架構與首頁

首頁第一屏（桌面 `d-01-home.png`、手機 `m-01-home.png`）依序是：頂欄（品牌、遊戲下拉、假導覽三字、搜尋框）→「CARDSCOPE · 公開 BETA」小標→大標「用中文查遍日、台、美版卡牌」＋一行副標→四個信任標籤（公開 Beta／五個 IP 分開整理／缺資料會標示待補／77,336 張收錄）→六張遊戲磚（全部遊戲＋五個官方 Logo）→「目前瀏覽 跨 IP 搜尋」說明列→「版本」下拉→四個分頁（最新收錄／商品分類／完整圖鑑／市場資料）→「商品圖鑑」區塊（目前只是一個虛線框說明「先選擇一個卡牌遊戲…」）。

- 使用者第一眼：從大標與副標能知道「中文查日台美卡」，從 Logo 磚知道有五個遊戲；但**第一屏沒有任何一張卡、沒有搜尋範例、沒有最近新增**，空的「商品圖鑑」佔掉第一屏下半，手機更是要捲 3 屏才碰到「選擇卡牌遊戲」格。
- 「能做什麼」的訊息被分散：副標講跨版本、信任標籤講資料狀態、搜尋框 placeholder 才給範例（噴火龍、魯夫、OP-05）。
- 首頁下半是資料完整度報表（`d-01-home-full.png`），含「遊戲王 中文名 1／缺口 14,683 張」等內部統計與冗長的圖例，再往下是一個深紫色的大 CTA「你的卡牌宇宙，一眼找到／開始探索」，標語與 HANDOFF 82 改過的首頁標語並存（舊標語仍在 CTA 裡）。

導覽元素是否重複／衝突：

| 元素 | 位置 | 狀況 |
|---|---|---|
| 遊戲下拉（頂欄「全部遊戲 ⌄」） | 頂欄 | 可用 |
| 遊戲磚／分頁籤（Logo） | 首頁大磚、遊戲頁分頁籤 | 可用，與下拉功能相同 |
| 「選擇卡牌遊戲」格 | 首頁下半 | **第三套遊戲選擇器**，與上方磚重複 |
| 頂欄「追蹤／探索／圖鑑」 | 桌面頂欄 | 是 `<b>` 元素，**不可點、不可聚焦**，但外觀像導覽、「探索」有底線；手機版隱藏 |
| 舊分頁「最新收錄／商品分類／完整圖鑑／市場資料」 | 首頁與遊戲頁 | 遊戲頁已有系列橫幅分頁，與之重疊；「最新收錄」無功能 |
| 系列橫幅（版本按鈕＋分頁＋磚） | 遊戲頁 | 主導覽，品質最好 |
| 版本下拉（首頁）／版本按鈕（遊戲頁） | 首頁／遊戲頁 | 同一概念兩種控制項，選項也不同（首頁含陸版、韓版） |
| 手機底部導覽（探索／卡片／資料／我的） | 手機 | 全是頁內錨點，不是頁面切換；首頁只有三個 |

## 3. 視覺一致性（對照主方案第 5 節「卡冊」）

| 規定 | 實測 | 落差 |
|---|---|---|
| 紙色底 `#EFEAE0` | 首頁 `rgb(239,234,224)` 相符；遊戲頁底色為 IP 淡色紙底（寶可夢為粉紅 `rgb(245,225,219)`） | 遊戲頁淡色底是方案允許的，但寶可夢頁整頁偏粉紅（`d-b1-game-pokemon.png`），觀感與「紙色」不同 |
| 字體 Noto Sans TC＋Space Grotesk | 首頁只載 Noto；遊戲頁 Noto 約 2900 元素、Space Grotesk 約 500（卡號、稀有度） | 符合；字重混用 400/500/700/800/850/900/950 |
| 操作區 ≥44px | 量測首頁／遊戲頁僅剩 6 個頁尾文字連結不足（如 143×19、36×17） | 基本符合，頁尾連結屬獨立項目，邊界案例 |

| 色票（紙／白／墨／灰／邊框）、IP 主色 | 首頁與下半部大量殘留舊色：薰衣草「目前瀏覽」列、`#7966c1`／`#6555a1` 紫字、藍紫資料區塊、深紫 CTA 橫幅、黃色（`--y`）按鈕與焦點框 | 這是目前最明顯的「兩套設計語言混在一起」，卡冊色票只覆蓋到上半 |
| 「不像範本」 | 圓角值 12+ 種（3、6、8、10、11、13、14、15、20px 等）；`99px` 膠囊在首頁與遊戲頁各約 40 個元素；10–11px 小字在遊戲頁約 255 個元素；漸層元素 324 個（含卡片金屬框的條紋） | HANDOFF 56 宣稱遊戲頁膠囊清為 0，實測仍有；未逐一歸因 |

看起來雜亂或像範本的地方：

- 首頁的「公開 Beta」徽章＋三個標籤＋「77,336 張收錄」外框列、資料完整度報表、深紫 CTA 橫幅，像三種不同的產品語言（`d-01-home-full.png`）。
- 深色槍鐵灰卡套框（`d-b1-game-pokemon.png`、`d-a2-2-results.png`）與白底資訊卡並存；SAMPLE 浮水印蓋在所有官方卡圖中央，遮住卡面文字（`d-a3-detail-info.png` 的技能說明被蓋住）。
- 卡片格的資訊密度：名稱、卡號、稀有度貼紙、版本小標、收藏星、數量加減，每張卡下半部都是控制項；瀏覽時視線被按鈕而不是卡圖佔據。

空狀態／載入／錯誤：

- 零結果：只有單行黃色提示（`d-e1-zero-results-landing.png`），語氣是開發者語言（「不以示範卡片填補」），沒有下一步建議；另一段「兔子還在尋找卡片」在頁面更下方。
- 載入：卡片格載入前是白框＋SAMPLE（沒有骨架）；遊戲頁／系列載入時有頂部提示「正在載入寶可夢卡片與圖片…」（`zoom200-game.png`）；手機詳細頁切版本是整頁全白（`m-c2-version-tw.png`）。日本官方站用灰色骨架方塊（`x-pkmcard-jp-search.jpg`）。
- 缺圖：設計是紙色底＋IP 色細帶的「圖片待補」，本次稽核沒有看到實例（可顯示圖片缺口集中在寶可夢 585 張、遊戲王 128 張）。
- 錯誤狀態：未稽核。

## 4. 無障礙快查

- 鍵盤完成流程 a：可以。Tab 順序為 跳到主要內容 → 品牌 → 遊戲選單 → 搜尋框 → 搜尋鈕 → 六個遊戲磚 → 版本下拉 → 四個舊分頁 → 檢視切換 → 稀有度 → 排序 → 只看收藏 → 第一張卡。**從搜尋框送出到第一張結果要按 19 次 Tab**（從頁首 22 次），沒有「跳到搜尋結果」。Enter 開窗後焦點到關閉鈕、`role=dialog`；Esc 關閉並回到原卡（良好）。
- 焦點可見：按鈕、磚多為 3px 黃色或 IP 色外框，良好；**搜尋輸入框聚焦時只有游標**（`outline: none`，外框本來就是 2px 黑線，`d-k1-search-focus.png`），沒有可辨識的焦點變化。
- 頂欄「追蹤／探索／圖鑑」不可聚焦，鍵盤使用者無法觸及，視覺使用者卻會以為能點。
- 對比：沿用 HANDOFF 51（寶可夢頁 1,220 個文字節點達標），本次未重量；注意遊戲頁有約 255 個 10–11px 小字節點，即使對比達標也偏小。
- 200% 縮放（720×450）：首頁、遊戲頁、詳細視窗皆無橫向溢出，頂欄改為不固定（`zoom200-game.png`）。
- 320px：頁面本身無橫向溢出，但詳細視窗內容被裁切（資訊方塊與下一張箭頭右緣超出 320，達 341–350px，`w320-modal.png`），不符合 WCAG 1.4.10 重排。
- 圖片替代文字：首頁 Logo 磚 `alt="寶可夢的 CardScope 非官方分類圖"`，實際顯示的是官方 Logo（ADR 0028），與實況不符。
- 其他：狀態沒有只靠顏色（稀有度有文字、NEW 有文字）；稀有度貼紙用顏色分三級但同時有文字，OK。

## 6. 問題清單（依影響排序）

### 嚴重

**1. 「名稱＋稀有度／版本」的自然查詢零結果，且沒有出路**
證據：`桃歹郎ex SAR`、`モモワロウex SAR` 皆 0 筆（API `searchScope: loaded-catalog-only`），`桃歹郎ex` 9 筆、`桃歹郎` 19 筆；零結果頁只有單行提示（`d-e1-zero-results-landing.png`、`d-a1-2-results.png`）。
可能的改法：A. 把查詢拆成 token，識別稀有度／編號／版本詞並轉成可移除的條件晶片（類 PkmnCards）。B. 零結果時顯示「拿掉『SAR』會有 N 筆」之類的放寬建議與可點範例。

**2. 搜尋結果品質：雜訊置頂、上限 40 卻顯示成總數、排序與分組不利找版本**
證據：`魯夫` 第 1 筆是寶可夢「Fluffy Berry」（`luffy` 子字串命中英文別名，`d-a4-2-results.png`）；API `candidateCount: 225`、`mayHaveMore: true`，標題寫「（40）」；結果依卡號排序，同一張卡的日／台／美版各占一格、跨 IP 混排。
可能的改法：A. 依「作品層卡片」分組（一張卡一列、版本在列內切換），按相關度與 IP 排序，詞界比對避免 `luffy` 命中 `Fluffy`。B. 標題改為「顯示前 40 筆，共約 225 筆」並提供「載入更多」與 IP／版本篩選晶片。

**3. 頂欄「追蹤／探索／圖鑑」是假導覽；收藏入口難找、命名不一**
證據：三者為 `<b>` 元素，不可點、不可聚焦；收藏／追蹤清單／CSV 藏在篩選工具列內，首頁看不到；用語「收藏／追蹤清單／件／張」混用（`d-d2-after-qty.png`、`d-01-home.png`）。
可能的改法：A. 移除假導覽，或改成真連結（探索＝首頁、卡冊＝目前遊戲、收藏＝獨立頁／抽屜）。B. 統一為「收藏」，頂欄與手機底部導覽各放一個固定入口，CSV 放在收藏頁內。

### 中

**4. 搜尋與選系列後的落點不佳，sticky 工具列遮擋內容**
證據：搜尋後 `scrollY` 約 1164（桌面）／1244（手機），結果標題被蓋住、第一列卡片上半被約 170px 的工具列蓋住（`d-a2-2-results.png`）；選系列後桌面系列資訊卡被切、手機橫幅被捲走（`d-b2-series-sv6a.png`、`m-b2-series.png`）。
可能的改法：A. 以標題為捲動目標並加足 `scroll-margin-top`，工具列改為捲動時才出現或縮成單列。B. 手機把橫幅收成可展開的「換系列」列，固定在卡表上方。

**5. 首頁第一屏沒有可用內容，且資訊架構重複**
證據：空的「商品圖鑑」虛線框、三套遊戲選擇器（頂欄下拉、Logo 磚、下方「選擇卡牌遊戲」格）、四個舊分頁（「最新收錄」無功能）、完整度報表與深紫 CTA 佔據首頁（`d-01-home-full.png`、`m-01-home-full.png`）。
可能的改法：A. 首頁改為「搜尋為主」：大搜尋框＋範例晶片＋五個 Logo 磚＋最近新增系列，完整度報表移到「資料」頁。B. 首頁改為「瀏覽為主」：直接顯示各 IP 最新系列橫幅（共用遊戲頁橫幅元件）。

**6. 遊戲頁預設載入整個 IP 的全部卡片**
證據：寶可夢日版預設「共 21,191 張，編號低到高」，航海王「共 4,915 張」，橫幅在上卻從最舊的卡開始（`d-b1-game-pokemon.png`、`d-b4-game-onepiece.png`）；手機頁高約 22,861px（前 100 張）。
可能的改法：A. 預設只顯示橫幅與「最新系列」的卡，使用者選系列才載入。B. 預設用「最新收錄」排序並刪除重複的舊分頁列。

**7. 詳細頁資訊層級與主方案不符**
證據：資訊分頁沒有資料來源、更新時間、圖片狀態、系列中文名（只在清單出現 SV6a）；沒有卡片文字（台灣官方有）；日版卡的價格頁顯示歐洲 Cardmarket 閃卡價，未說明對應哪個語言版本（`d-a3-detail-info.png`、`d-a3-tab-跨市場比價.png`）。
可能的改法：A. 在卡名下方加一行固定摘要（系列名・版本・來源・更新時間・圖片狀態）。B. 價格列註明「對應版本：美版／國際版」，並在日版沒有可靠價格時直接說明。

**8. 兩個空殼分頁與名稱錯置**
證據：「成交趨勢」永遠是「資料不足」，真正的走勢圖在「跨市場比價」；「使用者回報」只有「目前沒有使用者回報」，沒有表單（`d-a3-tab-成交趨勢.png`、`d-a3-tab-使用者回報.png`、`d-c7-price-chart.png`）。
可能的改法：A. 把走勢圖移到獨立的「價格走勢」分頁，無成交資料時隱藏「成交趨勢」。B. 「使用者回報」改為「回報資料錯誤」並連到既有勘誤／權利通知流程，或在有功能前先隱藏。

**9. 稀有度與資料狀態的呈現不一致**
證據：同一結果混有 `RR/SAR/UR` 與 `Double Rare/Special Illustration Rare/Hyper Rare/Rare Holo EX/NONE`；篩選下拉 38 個選項，含此系列不存在者（MUR、FUR、BWR…，無計數）；詳細頁顯示原文稀有度（`d-a2-2-results.png`、`m-b3-filter-sheet.png`）。
可能的改法：A. 顯示統一代碼（SAR/SR…）＋原文放 tooltip，`NONE` 改成「無標記」或「未知」（照 GLOSSARY 區分）。B. 篩選只列出目前範圍內有的稀有度並依高低排序。

**10. 卡圖載入與 SAMPLE 浮水印**
證據：卡圖直連官方站，載入前為白框＋SAMPLE 字（`d-a2-2-results.png`、`m-a4-2-results.png`），無頭瀏覽器 8 秒後 5/94 張、App 瀏覽器 6 秒 24/94 張（懶載入）；SAMPLE 蓋在每張官方卡圖中央，遮住卡面文字（`d-a3-detail-info.png`、`m-c1-modal-info.png`）。
可能的改法：A. 以骨架（沿用 IP 色細帶）取代白框＋SAMPLE，圖片載入後才顯示浮水印。B. 浮水印改為角落小標或只用在授權要求的來源。

**11. 載入時間偏長，缺少骨架與進度**
證據（無頭、暖伺服器）：首頁約 2–7 秒可操作、遊戲頁約 6–11 秒、直連卡片網址約 6–12 秒；手機切版本全白「正在載入…」（`m-c2-version-tw.png`）。
可能的改法：A. 分頁卡表首屏只取 24–48 張，視窗與列表使用骨架。B. 詳細頁先用列表已有資料立即渲染，版本資料到了再補。

**12. 視覺語言殘留兩套**
證據：薰衣草／紫字／深紫 CTA／黃色焦點與按鈕與卡冊色票並存；圓角 12+ 種、`99px` 膠囊約 40 個、字重 400–950 七種、10–11px 小字約 255 個（遊戲頁）（`d-01-home-full.png`；量測腳本結果見 0 節的方法）。
可能的改法：A. 整理 `index.html` 內嵌樣式與 `catalog-layout.css`，把舊紫／黃改成卡冊 token，圓角收斂為 2–3 級。B. 先只處理首頁（最顯眼），遊戲頁其餘慢慢收斂。

**13. 手機詳細頁資訊順序**
證據：先 4 個全寬資訊方塊，分頁與版本清單在約 868px 後（`m-c1-modal-info.png`、`m-c5-modal-scrolled.png`）；320px 時內容被裁切（`w320-modal.png`）。
可能的改法：A. 手機改為兩欄資訊小方塊（或單行 key-value）並把分頁列釘在卡圖下方。B. 修正 320px 的寬度與 `overflow`。

### 輕

**14. 搜尋框聚焦無可見變化**（只有游標，`d-k1-search-focus.png`）；可能的改法：聚焦時加 3px 焦點外框或底色變化。
**15. 鍵盤要 19 次 Tab 才到第一張結果**（`d-k2-first-card-focus.png`）；可能的改法：在結果標題前加「跳到搜尋結果」或讓搜尋後焦點移到結果標題。
**16. 首頁 Logo 磚 alt 文字寫「非官方分類圖」**，與 ADR 0028 的實況不符；可能的改法：改為「寶可夢卡牌遊戲 Logo」。
**17. `canonical` 與標題版本不一致**（標題為日版，canonical 指台版 printing）；可能的改法：canonical 與當前 `card=` 一致，或明確選定作品層代表版本並在標題反映。
**18. 系列磚名稱單行省略、日中名稱混用**（`d-b4-game-onepiece.png`）；可能的改法：磚內允許兩行或點擊／懸停顯示全名，日版中文名未補時顯示「原名＋中文待補」標示。
**19. 分享鈕在無剪貼簿權限時變成「請複製瀏覽器網址」**（`d-c3-after-share.png`）；可能的改法：行動裝置用 Web Share API，其餘顯示可選取的網址欄位。
**20. 首頁同時有六個格子的持續反光動畫**；可能的改法：只讓「全部遊戲」格持續動，其餘 hover 才動（或保留，視產品決策）。

## 7. 需要產品決策的問題

1. **首頁以搜尋為主，還是瀏覽為主？** 現狀兩者都做一半（搜尋框在頂欄、瀏覽靠 Logo 磚＋下方重複的遊戲格＋完整度報表）。
2. **搜尋要支援「名稱＋稀有度／版本／編號」的自然語句嗎？** 還是只比對名稱，其餘靠篩選？（問題 1）
3. **搜尋結果的單位：作品層卡片（一張卡、版本在內切換）還是 Printing（每版一格）？** 這決定「三次互動找到正確印刷版本」怎麼定義與量測。
4. **首頁搜尋要不要和遊戲頁一致，先選版本再搜？** 目前首頁跨 IP 跨版本混排，遊戲頁限定版本。
5. **遊戲頁預設內容**：橫幅＋整個 IP 卡表（現狀）、只有橫幅直到選系列、還是橫幅＋最新系列卡片？「最新收錄」與其他舊分頁列要留還是刪？
6. **收藏／追蹤**：統一叫什麼？入口放在哪（頂欄固定項、手機底部「我的」）？要不要做會員跨裝置（HANDOFF 97 的方案）？CSV 保留嗎？「加星」與「數量」要合併成一個動作嗎？
7. **頂欄**：假導覽三字要刪、改真連結，還是改成別的（例如「資料」「收藏」）？遊戲切換只留一套還是保留下拉＋磚＋分頁籤？
8. **SAMPLE 浮水印**：是否所有官方卡圖都加？還是只在授權要求的來源（如芙莉蓮官方 SAMPLE 圖）？
9. **詳細頁**：要補「來源／更新時間／系列名／卡片文字」到資訊分頁嗎？卡片文字能否取自台灣官方詳細頁（來源政策與授權需另議）？空殼分頁（成交趨勢、使用者回報）隱藏、改名還是做成真功能？
10. **價格**：日版卡顯示歐洲／美國參考價時，要不要明示對應哪個語言版本？日版沒有可靠價格時是否直接不顯示價格分頁？
11. **稀有度**：統一成 CardScope 代碼並以原文為輔？「NONE」要顯示成「無標記」還是「未知」？
12. **視覺**：要不要完全落實卡冊色票（拿掉殘留紫與黃）？寶可夢頁整頁粉紅底是否保留？首頁六個持續動畫格是否保留？
13. **效能取捨**：卡圖維持直連官方站（授權風險已接受）還是自家快取／代理？首屏卡數 100 要不要降到 24–48 並加骨架？
14. **手機導覽**：底部四個錨點按鈕要不要改成真正的頁面／分頁（探索／卡冊／收藏／資料）？
