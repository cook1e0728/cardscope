# CardSeek 全站體檢規格書（2026-11-24）

> 唯讀體檢，沒有改任何網站程式。對象：正式站 https://cardseektcg.com 與 main（5a3112a）的原始碼。
> 做法：agy `/swarm`（Orchestrator Argon）分四條線平行檢查，共 69 條。再由 Claude 用原始碼與 Playwright 實測核對：高嚴重度與資安項目全部核對，其餘抽查；沒核對的標「未核對」。另附 Claude 自己的正式站實測。

## 一頁摘要（白話）

**整體：** 網站沒有立即會被攻破的漏洞。沒有找到外洩的密鑰；外部資料（eBay、時事、卡片）顯示前都有跳脫；CSP 只允許指定的程式碼執行。主要問題在四方面：「錯誤時看起來像沒資料」、「鍵盤與讀屏使用者的細節」、「字級與對比不一致」、「詳細側板資訊太擠」。

**最該先做的 5 件事：**
1. **首頁導覽會搶走打字中的焦點**（HCI-04，高，實測屬實）：第一次進站的人正在搜尋框打字時，導覽在 1.4 秒後彈出並搶走焦點。改成使用者一有動作就不自動彈出。
2. **資料讀取失敗時被畫成「沒有資料」**（HCI-05，高）：首頁榜單、行情漲跌讀取失敗時，畫面寫的是「無資料」而不是「暫時讀不到、按此重試」。Render 停用期間更容易遇到。
3. **首頁頁首的帳號鈕，鍵盤焦點框幾乎看不見**（UI-03，高，實測屬實）：深紫底配深色框（約 1.07:1）。改成淺色框，一行 CSS。
4. **180 天收藏同步清理排程還沒套用**（SEC-10，中，SQL 查證屬實）：隱私說明承諾了，但資料庫裡沒有這個排程。需要使用者在 Supabase 副庫 SQL Editor 貼上執行。
5. **Worker 對 HEAD 與未知 /api 路徑回 502**（SEC-01，中，實測屬實）：應該回 404／405，並且不要轉發給已停用的 Render。

**其次：** 手機版收藏後「＋」鈕被切掉 3px（HCI-06）。矮視窗（筆電放大 200%）開側板會蓋住卡牆（HCI-07）。內頁缺 h1（HCI-08）。字級散落 15／18px（UI-06）。框線與次要小字對比不足（UI-02、UI-04）。停用按鈕沒有停用外觀（UI-07）。

**agy 說錯的：** SEC-11（ID 過濾其實安全）、UI-01（關於頁區塊實際排版正常）、SEC-05 前半（PKCE 擋住了 state 繞過），以及 HCI-01（Esc 層級實測未重現）。

**設計調整（DES-01～15）** 都是主觀建議，方向是「詳細側板減少盒中盒、價格先大後小、卡牆價格固定兩行、長文行寬收窄」，動工前要先出預覽給使用者看。

**建議分三批：**
- 第 1 批：HCI-04、HCI-05、UI-03、SEC-01、SEC-10，加上 SEC-05 後半（登入失敗沒提示）。都是小改。
- 第 2 批：對比、字級、停用狀態、h1、手機「＋」裁切、矮視窗側板、tablist 方向鍵、雙層 dialog。
- 第 3 批：DES 系列排版精修，需要先看預覽。

## 核對欄的意思

- **成立**：Claude 看過原始碼或在正式站實測過，確實如此。
- **不成立**：查證後不是這樣。
- **部分成立**：同一條裡有對有錯。
- **實測未重現**：照描述實測，結果正常。
- **主觀**：設計意見，沒有對錯。
- **未核對**：只抽查了別條，這條照 agy 原文，使用前要再看一次。

嚴重度若和 agy 原本評的不同，會寫「中（agy 原評 高）」。
