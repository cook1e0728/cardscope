# CardScope 產品、資料與 UX 主方案

狀態：已核准的執行基準
更新日期：2026-10-01

## 產品定位與成功標準

CardScope 是「繁體中文玩家的跨語言、跨版本 TCG 查證與收藏探索入口」。資料正確性、中文導覽與搜尋優先於價格功能。

核心成功標準：玩家能在三次互動內找到正確印刷版本，並立即看見資料來源、更新時間、語言／地區、圖片狀態及價格性質。

全站固定原則：

- 不使用付費服務、不購買代理、不繞過登入、驗證碼、Cloudflare 或反爬限制。
- 不複製卡拍拍、Pinterest、Reddit 的 Catalog 或圖片；這些網站只用於理解玩家需求、用語與 UX 痛點。
- 沒有可靠資料時顯示「尚未取得可靠資料」，不產生假卡、假價格、假交易量或假趨勢。
- `listing`、`buyback`、`sale` 永遠分開，不把掛牌或買取標為成交價／店售價。
- 來源授權不明時採保守策略，但不阻塞其他合法來源與功能的開發。

## 執行順序

### 0. 收斂 Git 歷史

每輪開始都從 GitHub 最新 `main` 建立乾淨整合分支。舊工作區只能逐項移植已驗證行為，不可把落後分支整包合併或直接推上 `main`。衝突必須人工解決，並保留既有測試和使用者未提交檔案。

### 1. Supabase 與卡片身分

- 先核對正式 schema、migration history、資料筆數、重複 migration 編號和 coverage。
- migration 只允許新增式、可重複執行及向前相容變更；不改已套用歷史、不刪表、不清資料。
- 作品層保存角色與跨語名稱；printing 層保存語言、地區、彈數、編號、稀有度、圖片與來源。
- 顯示與補資料優先序固定為：日版 → 台版 → 美版 → 韓版／其他。
- 只有官方編號或可靠 provider ID 能合併版本；名稱相似只可作搜尋別名，不可當作身分證據。
- Supabase 無法使用時，`data/catalog.json` 保持唯讀 fallback。

### 2. 五個 IP 的資料完整度

依序完成，每個來源獨立限流、快取、續傳與失敗隔離：

1. 寶可夢：日版全系列、卡表、卡盒及商品封面，再交叉驗證台、美、韓版本差異。
2. 遊戲王：YGOPRODeck 提供基礎 metadata，官方 Neuron 驗證卡號、系列與名稱。
3. 航海王：官方卡表驗證身分；圖片依個別來源權利政策處理。
4. 排球少年 Vobaca!! BREAK：所有公開彈數、牌組、PR／特典和產品圖。
5. Weiss Schwarz《葬送的芙莉蓮》：公開系列、平行版本、PR／特典與官方 SAMPLE 圖；浮水印必須保留。

每筆來源資料需保存 `sourceId`、來源網址、查詢時間、語言、區域、資料狀態和圖片權利狀態。正式啟用來源前檢查網站條款、robots 與速率限制。

#### Phase 2A 執行狀態（2026-09-15）

- 已建立版本控管的系列級 baseline registry；五個 IP 的全域完整分母仍維持 `unknown/null`，不把目前收錄量冒充完整度。
- 來源回報的 `total`／`printedTotal` 只按 `IP + 地區 + 語言 + 系列 + provider` 範圍保存；不跨地區加總為單一 IP 總數。

#### Phase 2B 回歸稽核（2026-09-27）

- 上述稀有度「已完成」是當時升級後的驗收紀錄，不代表目前正式庫狀態。唯讀稽核發現寶可夢台版 7,436 個 printing 的 `rarity`、`rarity_code`、`rarity_label` 現皆為空；S10a、S10P、S11、SV8a 的卡片層稀有度仍在，但 printing 層已回歸為空。公開完整度應分別呈現卡片與 printing 的已知缺口，不能用卡片層值冒充印刷版本資料。
- 9 月 23／24 日的私有升級批次記錄顯示卡片與 printing 均曾寫入；9 月 24 日 09:40–09:41 UTC 的 TCGdex 繁中同步晚於升級，受影響 printing 的更新時間落在同一分鐘。同步程式會把來源清單缺少的稀有度作為 `null` 送入合併更新，與回歸吻合。先部署「空值不覆寫」保護並驗證，才可依原始已審核候選進行可稽核的精確修復。
- 私有候選有 796 筆已升級的 printing 稀有度紀錄，對應 786 個唯一 printing；其中 10 筆舊候選是同一目標的重複證據，且有較新的完整批次紀錄。正式修復須逐一驗證身分、來源、稀有度、原批次與目前空值，保留全部候選的稽核鏈；不可從卡片層反推版本稀有度。
- 9 月 27 日已先上線同步防護，再以遠端 migration `20260926200419_repair_pokemon_tw_printing_rarity` 精確修復 786 個台版 printing 的三個稀有度欄位；線上複核 786/786 與原候選代碼吻合，私有 append-only 稽核包含全部 796 候選、10 筆排除的舊重複證據，以及 786 筆修復前後快照。這不是 7,436 個台版 printing 的全面補齊；沒有已審核同版本證據的卡仍維持空值。

- 2026-10-01 唯讀核對正式庫：日版寶可夢只有手寫 SV4a Seed（1 系列、1 卡、1 printing，`source`／`provider_id` 皆空）；台版 7,436、美版 20,635 個 printing。`tcg_series` 的 `unique(game_id, official_code, region)`、各表 `(source, provider_id)` 唯一鍵與 printing 自然鍵均為 valid；`tcg_cards` 的 canonical trigger 在 canonical ID 相同時會合併名稱與別名。
- 範圍：單一乾淨系列、來源卡數 ≤100、一份 manifest 即一個交易（全有或全無）。挑選條件：取回數＝`cardCount.total`＝`cardCount.official`、manifest 零隔離、不在 `svp`／`sve`／`CS1.5`／`SV5K`／`SV4a`／`PMCG1` 隔離清單、有上市日期，優先台版已收錄的朱紫世代系列，多個符合時取卡數最少者。系列待來源可連線後附證據確認。
- 身分：Provider ID（`tcgdex-ja`）為主身分，printing 自然鍵為一致性檢查，兩者任一衝突即中止。Card／printing 使用可讀 ID `pokemon-tcgdex-ja-<系列>-<編號>`，canonical 與 card 1:1、不連結台／美版（見 `docs/adr/0001-jp-canonical-isolation.md`）；任何 ID、自然鍵或 canonical 碰撞即中止。
- 寫入：只 INSERT series／card／printing 與稽核紀錄，不 UPDATE、不補空值；只寫 `name_ja`，`name_zh` 不猜譯；`image_url` 空、`image_rights_status='not-provided'`；`data_status='pending'`（localId 尚未驗證為官方卡號）。
- 執行：新增式 migration 建立 private 追加式稽核表（禁止修改與 truncate）及僅 `service_role` 可呼叫的匯入函式；函式在單一交易內取得系列 advisory lock、重驗 manifest／source／seed hash、檢查碰撞並寫入。相同 hash 重播回傳 `replay=true` 且零異動；同系列已匯入後送來不同 hash 一律中止，不做差額增量。
- 驗證與發布：Node 測試＋本機 PostgreSQL 16 SQL 情境測試（成功、重播、不同 hash、各類碰撞、中途回滾、權限拒絕；不加入 CI）→ 正式唯讀複核 → migration → 正式 dry-run（執行後主動回滾）→ 真實匯入 → 立即重播 → 前後差異複核（台／美版零異動）→ 正式 API 抽查 → 文件。migration 與真實寫入前各需使用者確認；資料庫不做破壞性回滾。
- 公開：通過 API 抽查後立即出現在卡表、搜尋與 coverage，標示繁中名稱尚未取得；日版系列分母維持 unknown，只標示來源觀測數。
- 不在 pilot：SV4a Seed 維持原狀，之後另行核對是否認領；PMCG1 變體數超出總數只作來源品質問題，不納入完整度，原因另行調查；圖片、商品、價格、跨版本連結與多批大系列。

### 3. 圖片與品牌辨識

- 五個 IP 導覽統一使用可靠官方 Logo；「全部遊戲」使用 CardScope 自有的抽象卡冊／收藏桌插圖。
- 卡盒、牌組、特典、周邊與單卡分開分類，Logo 不計入商品數。
- 圖片政策以來源為單位：可展示、使用者已接受風險、僅可外連、不可展示。不可再用單一全域旗標代表所有來源。
- 圖片失效時，只能嘗試相同 printing 的可靠來源，不拿其他語言或版本圖片冒充。
- 2026-09-28 唯讀盤點：正式庫 32 件實體封面商品均有圖片（航海王 10、排球少年 18、芙莉蓮 4），寶可夢與遊戲王目前沒有實體卡盒商品列；另有 1,041 筆系列索引，740 筆有圖、301 筆缺圖。系列索引圖不是實體卡盒封面，不可混算。來源註記的 `risk-accepted` 不等於授權；新增官方 IP 封面前仍須有可展示的權利依據，否則只用明確標示的非官方中性導覽圖。
- 公開圖片覆蓋率的「可顯示」與「缺口」必須使用同一來源政策判斷，且只以目前收錄卡片為分母；圖片網址存在數與原始關聯稽核另外呈現。`risk-accepted` 並非著作權授權，可顯示也不保證實際載入成功。

### 4. 導覽、搜尋與詳細頁

資訊架構固定為：`IP → 語言／地區 → 世代或分類 → 系列／產品 → 卡片`。

- IP 切換器與搜尋欄下方頻道由同一設定產生；桌面用置中 modal，手機用 bottom sheet，提供遮罩、清楚關閉、焦點鎖定、Escape 與焦點返回。
- 系列使用繁體中文主標題；副標顯示原文、代碼、上市日期、版本、資料完整度及來源狀態。
- 支援世代折疊、快速跳轉、最近瀏覽、可分享網址，以及返回後保留搜尋／篩選／排序。
- 搜尋涵蓋繁中、日、英、韓名稱、別名、角色、編號、彈數及產品名稱。美版 Charizard 圖片的繁中主名稱仍是「噴火龍」。
- 各 IP 統一支援稀有度、價格、編號、語言／地區、系列、最新發布、編號與價格升降序。
- 卡片詳細頁使用永久網址，並列同作品的各國 printing，但不混合價格。

固定搜尋驗收詞：`luffy`、`魯夫`、`噴火龍`、`Charizard`、`リザードン`、`超夢`、`夢幻`、`黑魔導女孩`。

### 5. 視覺與無障礙

風格為「收藏家的桌面」：背景 `#F7F5EF`、表面 `#FFFFFF`、主文字 `#171717`、次文字 `#686863`、邊框 `#D9D6CC`、主色 `#007F7A`、選取色 `#FFD600` 配黑字。

- 只使用極淡紙張質感及低陰影，不在卡圖上製造假閃卡材質。
- 動畫 120–180ms、位移不超過 4px，支援 reduced motion。
- 操作區至少 44×44px；支援鍵盤、可見焦點、200% 縮放，狀態不可只靠顏色傳達。
- 目標為 WCAG 2.2 AA。

### 6. 市場資料與趨勢

- 只比較相同 printing、來源、價格種類、品況和幣別，兩次觀測至少相隔 24 小時。
- `/api/trends` 必須提供訊號／價格種類、來源和連結、前後觀測時間、樣本數及適用範圍。
- 若資料只有遊々亭買取，介面名稱使用「單一來源買取漲幅」，不可稱「人氣漲勢」。
- 暫不建立人氣排行、不用 Reddit 熱度推算卡片行情，也不加入使用者追蹤。

## 公開介面相容性

保留既有 `/api/catalog`、`/api/cards`、`/api/search`、`/api/cards/:id`、`/api/cards/:id/market`、`/api/trends`、coverage／health／sources 與管理端點。擴充查詢與欄位時保持舊參數可用；來源故障必須回傳清楚狀態，不讓單一 provider 令整個 Catalog 失效。

## 驗收與發布門檻

- 單元測試：多語名稱、printing 合併、稀有度、篩選、排序、價格種類與圖片政策。
- 來源測試使用固定 fixture；線上 canary 另行執行，避免 CI 只依賴外站即時狀態。
- Playwright 覆蓋桌面／手機 IP 切換、搜尋、篩選、最近瀏覽、詳細頁、返回、分享、鍵盤、200% 縮放、慢網路、缺圖、零結果和 reduced motion。
- 效能目標：暖機搜尋 P95 < 800ms、INP < 200ms、LCP < 2.5s、CLS < 0.1。
- 發布順序：完整測試 → Supabase 唯讀稽核 → 必要的新增式 migration → 再次確認遠端 `main` → 更新 GitHub → 監控 Render → 線上五 IP／關鍵詞／圖片／手機 smoke test。
- 應用失敗以 revert 回復；資料庫不做破壞性回滾。

## 模型分工

- GPT-6 Luna Max：日常實作、測試、資料同步、文件、整合與部署驗收。
- Luna workers：只處理可獨立、檔案不衝突且驗收條件清楚的工作包。
- GPT-6 Sol advisor：只處理授權／來源政策、資料完整性、破壞性 migration、重大架構、難解根因及最終高風險 UX 決策；提出裁決後由 GPT-6 Luna 實作。
- 不聲稱 Luna Ultra 已運行；目前專案鎖定的可用工作模型是 Luna Max。

## 自主決策邊界

一般 UI、資料清理、測試與非破壞性發布判斷可直接執行，不需再次詢問。新增費用、破壞性資料操作、需要使用者提供新密鑰、或必須接受新的法律／授權風險時才停止並回報。
