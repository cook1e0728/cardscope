# 日版 ex／EX／GX／V／VMAX／VSTAR 卡以「去掉後綴的日文名」對應唯一官方中文名推導

ADR 0013 的同名推導要求日文名完全相同。2026-10-24 日版缺中文名 3,391 張，其中日文名為「基底＋後綴」（ex、EX、GX、V、VMAX、VSTAR）的有 1,107 張，多半是 SM 世代 GX（629）與 XY 世代 EX（292）：資料庫裡沒有同名的官方卡，但有同一隻寶可夢的其他後綴或無後綴官方卡（例如沒有「ジラーチGX」的台版，但有「ジラーチ」→「基拉祈」）。

決定（2026-10-24，使用者同意採用）：日版卡沒有中文名、日文名以上述六種後綴之一結尾時，若去掉後綴後的日文名（比對時 NFKC 並去掉空白，同 ADR 0013 的 `private.jp_name_key`）在**官方依據的日版卡**中只對應**唯一一個**中文名基底，就採用「中文名基底＋同一後綴」作為 Derived name。

證據與規則：

- 證據只取日版卡中 `nameZhBasis` 為 `tw-official` 或 `tw-official-same-number` 的卡；`derived-*` 與本規則寫入的名稱都不是證據，避免推導再推導。
- 無後綴與有任何後綴的官方卡都算證據：有後綴的官方卡必須日文與中文後綴相同（日 `GX` 對中 `GX`），並從中文名去掉該後綴取得基底；後綴對不上的證據視為「證據矛盾」，該基底不推導。
- 同一個日文基底所有證據的中文基底必須逐字相同。不唯一者一律不寫（例如サーナイト：`沙奈朵`／`M沙奈朵`；ミミッキュ：`謎擬Q`／`謎擬Ｑ`，全形半形差異在此不做 ADR 0013 補充那樣的歸併）。
- 後綴寫法沿用台版官方：後綴接在基底後面不加空格（`鬃岩狼人ex`、`皮卡丘V`、`伊布VMAX`、`快龍GX`、`胡地EX`，大小寫與日版相同）。唯一的例外是名稱本身帶空格的官方寫法（`月月熊 赫月 ex`），改採證據中觀察到的分隔；同一基底的證據分隔不一致就不寫。
- 基底帶 Source name markup（`<火箭隊的>`、方括號、結尾括號）者不推導，不在此規則內正規化。
- 只填空值；不連結 Canonical card；不處理無後綴的卡（那是 ADR 0013）。

稽核欄位（寫在卡片 `metadata`，不動既有稽核表）：

- `nameZhBasis: 'jp-name-affix-unique'`
- `nameZhRule: 'adr-0053'`
- `nameZhSourceCardId`：提供中文名基底的第一張官方依據日版卡
- `nameZhAffix`：接上的後綴

`private.catalog_jp_derived_name_audit` 的 `rule` 以 CHECK 限定為 `adr-0013`，且列數上限 100，所以本規則不寫入該表，而是用卡片 metadata 逐張留證據；要新增專用稽核表須另做 migration。

寫入實作為 `scripts/fill-pokemon-jp-zh-name-affix.mjs`：預設 dry-run；`--apply` 以交易分批（預設每批 100 張，上限 1,000），SQL 端再驗證目標仍為日版、日文名一致、中文名仍為空，引用的官方卡仍存在且有官方依據；重跑計畫應為 0 張。只更新 `name_zh`、`metadata`（日版沿用 ADR 0013 的做法：`aliases`、`search_text` 只放卡號、也沒有 `tcg_card_names` 列；`search_names` 為產生欄位，Canonical card 名稱由既有觸發器同步）。

## 不適用情況

- 無後綴的日文名（寶可夢、訓練家、能量）：沒有官方同名卡時維持空值。
- `BREAK`、`LEGEND`、`LV.X`、`☆`、`δ` 及其他後綴；`Mega`、暗黑、火箭隊等前綴不是後綴問題，由日文名整體比對（前綴相同才會對到同一個基底，如「ヒスイ ドレディア」）。
- 日文基底在官方依據的日版卡中完全沒有出現（243 張，多為只有 GX／EX 版本的寶可夢與 TAG TEAM 組合）、基底對應多個中文名（12 張）、證據分隔不一致（1 張，ガチグマ アカツキ）。
- 日版與台版對同一隻寶可夢的官方中文名在不同卡片上不一致時（上例），要先由人確認哪個是正確寫法。

## Consequences

- 2026-10-24 寫入 851 張（EX 274、GX 403、V 116、VMAX 45、ex 10、VSTAR 3），分 18 批，每批 50 張約 1.2 秒；日版中文名比例 84.0%（17,800／21,191）→ 88.0%（18,651／21,191）；重跑計畫 0 張。
- 這些名稱來自台灣官方的同一隻寶可夢名稱，但這張卡本身未經台灣官方確認，所以仍是 Derived name，不是身分證據。卡片詳細頁目前只替 `derived-same-name`、`derived-cross-series` 顯示「同名推導」標示；`jp-name-affix-unique` 要在 `ui-enhancements.js` 加進同一個清單才會顯示。
- 若之後台版官方補上這些卡，ADR 0003／0011／0024 的官方名稱仍優先；本規則只填空值，不覆寫。
