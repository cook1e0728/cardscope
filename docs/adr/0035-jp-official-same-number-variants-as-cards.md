# 日版同號同名的多個官方版本拆成同一作品層下的多張卡，以「版本 k」命名

ADR 0025 把同系列、同卡號、同日文名的多個官方詳細頁合併成一張卡。2026-10-10 查證發現這些頁面實體上並不相同：SH 040 きずぐすり 兩頁右下的牌組標記不同（火球鼠剪影／皮卡丘），SI 101 ブイゼル 兩頁的卡片背景紋路不同。合併後收藏者無法分開登記，主圖也只有編號最小的那一頁。

決定（2026-10-11，使用者選擇「拆成多張卡＋中性編號」）：

- 每張 ADR 0025 合併的卡（`officialCardIds` 至少 2 個），編號最小的官方頁保留原卡 ID；其餘官方頁各新增一張卡 `<原卡 ID>-v<k>`（k 依官方卡片 ID 數字排序，從 2 起），與原卡同一個 Canonical card。這與排球少年 S／極／極P 同卡號多張卡的做法一致，既有收藏、分享連結、搜尋不受影響。
- 新卡沿用原卡的卡號、日文名、中文名（含依據）、稀有度與資料狀態；官方 ID、詳細頁網址與官方卡圖（ADR 0031）用該頁自己的。
- 命名用中性編號：卡片與版本列的 metadata `variantName` 為「版本 1」「版本 2」…（版本列另有 `variantKey` `v1`、`v2`）。官方文字資料沒有寫出差異所在，只能從卡圖看出，因此不以人工描述命名，避免標錯；之後若要補「牌組標記：皮卡丘」這類描述，再另行決定。
- 不改成同一張卡下的多個版本列：版本列以「卡片＋地區＋語言＋系列代碼＋卡號」唯一，同卡號兩列需要改資料表結構。
- 寫入：`private.split_pokemon_jp_official_variants`（migration `20261011080000`）。每次最多 100 張新卡，同一原卡的所有額外官方頁必須在同一份計畫；核對原卡來源、官方 ID 清單與排序、新卡 ID 與序號、圖片網址；dry-run、重播零異動、追加式稽核 `private.catalog_jp_variant_split_audit`。原卡只新增 `variantIndex`／`variantName`／`variantRule` 與版本列的 `variantKey`／`variantName`。
- 前端：卡片格子顯示「版本 k」標籤；詳細頁「收錄版本」每列列出版本名稱，可點擊切換到該版本的卡圖（依序執行 71 的切換功能）。

## Consequences

- 2026-10-11：27 個系列 210 張原卡，新增 249 張版本卡（SI 126、SVI 28、SH 19、WAK 17、SML 12 等），6 份計畫寫入＋重播零異動；249 張新卡皆有官方卡圖。計畫 `docs/evidence/pokemon-jp/official-series/variant-split-plans-20261011.json`。
- 原卡 metadata 仍保留 `officialCardIds`（列出所有版本的官方 ID），作為拆分依據。
- 之後 ADR 0025 補卡若再遇到同號同名多頁，應直接依本 ADR 拆成多張卡。
