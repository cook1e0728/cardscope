# UI 改版：以「找得到」為主、手機優先，從局部修正開始

**狀態：已採用（2026-10-19，grill 兩輪，使用者同意全部照建議執行）。依據 `docs/research/ui-audit-20261018.md` 的稽核。**

主方案的成功標準是「三次互動內找到正確印刷版本」。稽核發現：自然語句查不到（「桃歹郎ex SAR」0 筆）、搜尋結果排序把別名命中排第一（「魯夫」第一筆是 Fluffy Berry）、總數顯示錯（寫 40、實際約 225）、頂欄導覽點不了、首頁第一屏沒有卡、遊戲頁預設載入整個遊戲、詳細頁有空殼分頁。

決定：

- **方向**：以找得到為主、看得懂為輔；手機優先；局部修正起步，首頁與搜尋可到中幅重整。流程類決定照建議直接做，視覺類先做預覽。
- **首頁（Q5）**：第一屏是搜尋——大搜尋框＋可點的範例（卡名、卡號寫法）＋遊戲入口＋最新系列。內部統計（覆蓋率報表）移出首頁。
- **自然語句搜尋（Q6）**：伺服器把查詢中的稀有度代碼（依 `data/rarity-rankings.json` 的代碼與別名）與版本詞（日版／台版／美版／韓版、JP／TW／US／KR）拆成篩選條件，其餘當卡名查；回傳 `meta.parsed` 讓介面顯示「已套用：SAR、日版」並可取消。仍為零結果時提示「試試只搜卡名」。
- **排序與數量（Q7）**：卡名完全符合 → 開頭符合 → 包含 → 只有別名／文字符合；同一遊戲的結果相鄰。標題顯示真實總數，提供「載入更多」。
- **頂欄（Q8）**：改為真連結「搜尋／圖鑑／我的收藏」，手機底部導覽同三項；收藏統一叫「我的收藏」。
- **遊戲頁（Q9）**：預設只顯示系列橫幅與最新系列的卡表，「全部卡片」需點選才載入。
- **詳細頁（Q10）**：分頁改為「資訊／價格／走勢」；「成交趨勢」改名為參考價走勢並移入走勢圖；「使用者回報」在有表單前隱藏；資訊分頁補系列名、資料來源、更新時間。
- **SAMPLE（Q11，視覺，先預覽）**：主方案只要求保留芙莉蓮官方卡圖本身的 SAMPLE；我們自己疊的那層改小、放角落，做成預覽給使用者確認。
- **稀有度（Q12）**：統一顯示代碼、滑過看全名；篩選只列目前範圍實際有的稀有度；`NONE` 顯示「無標記」。
- **收藏 v0（Q13）**：併入，排在上述之後（依賴「我的收藏」入口）。範圍見 `docs/research/collections/README.md` 的 v0。

## Consequences

- 主方案第 5 節要補「首頁以搜尋為主、頂欄三項導覽、詳細頁三分頁、稀有度顯示代碼」。
- 自然語句解析只做稀有度與版本詞兩類，規則可測、不猜；卡號空格寫法已在依序執行 106 處理。
- 前端仍是單檔密集寫法，詳細頁實際由 `ui-enhancements.js` 渲染（覆蓋 `index.html` 同名函式），改動時兩處都要確認。
