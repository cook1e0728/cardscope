# 收藏 v0：只存在使用者瀏覽器，不登入、不上傳；主方案改成「不做行為追蹤」

**狀態：已採用（2026-10-19，使用者同意照建議執行；ADR 0044 Q13 併入，範圍見 `docs/research/collections/README.md` 的 v0 與決定 1、2、9、10）。**

主方案第 6 節原本寫「暫不建立人氣排行、不用 Reddit 熱度推算卡片行情，也不加入使用者追蹤」。這句可以讀成「不做使用者行為追蹤」，也可以讀成「不做使用者收藏／追蹤清單」。本決定把語意固定為前者：**不做使用者行為追蹤（人氣、瀏覽軌跡、廣告、分析）；收藏是使用者主動儲存的資料，v0 免登入，v1 起可選登入。** 已同步修改 `docs/PRODUCT_PLAN.md`。

決定（v0，不含登入、不新增服務、沒有 migration）：

- **資料只在這台裝置**：沿用 `localStorage` 的 `cardscope-favorites`、`cardscope-watchlist`、`cardscope-watchlist-meta`，不新增鍵、舊資料不改名；伺服器不蒐集、不儲存任何收藏內容，也不加分析。介面固定說明「只存在這台裝置」，並建議匯出備份。
- **身分**：以實體卡 id（`tcg_cards.id`）為鍵，同時存 `canonicalId`。圖鑑列的 id 是實體卡、搜尋列的 id 是作品層，所以新加入一律取畫面上那個版本的實體卡（`cardOpenId`）；舊資料可能混有兩種 id，開啟「我的收藏」時逐筆向 `/api/cards/:id` 查：已是實體卡就補快照；作品層只有一張實體卡就換成那張；有多張（日／台／美版）**不猜**，標「版本待確認」，讓使用者從清單選；查不到或網路失敗就原封不動保留。任何情況都不刪舊資料。
- **欄位**：張數（1–999）、品況（NM／LP／MP／HP／DMG／鑑定卡）、版本（沿用 `price_snapshots.variant` 詞彙，例如 holo、reverse）、備註（200 字）。v0 每張卡一列，同一張卡不同品況要分開記請寫在備註；購入價與損益不做（決定 10，v2 才顯示）。
- **參考總值**：新增 `POST /api/prices/reference`，body 只接受 `{cardIds:[…]}`，1–100 個字串（每個 ≤128 字、不含控制字元與引號／反斜線、多餘欄位直接 400），body 上限 20 KB。回傳每張卡每個 `provider＋variant` 的最新 `price_snapshots` 一列（原幣、金額、新台幣換算用既有 `getTwdRates()`、快照日期）；沒有快照的卡回空陣列。**只做一次 `price_snapshots` 查詢**（主鍵 `card_id,provider,variant,snapshot_date` 的前導欄位 `card_id` 已可用，不需新索引、不需 migration），依日期新到舊最多取 5,000 列，截斷時 `meta.truncated`；不打任何外部 TCGdex。
- **總值規則**（沿用 README 第 2.1 節與決定 9）：Cardmarket、TCGplayer **分來源小計，不相加**；所選版本必須和快照 variant 完全相同，沒選版本時該來源只有一個 variant 才計入、有多個就提示「請選擇版本」，不替使用者挑；品況不調整價格；鑑定卡不計入；無快照的卡標「未計入：尚無參考價快照」；一律標示為平台參考價、不是成交價或台灣行情，顯示快照日期與匯率日期（備用匯率會註明）。不出現賺賠字樣。
- **備份**：JSON（`{app:'cardscope-collection',version:1,items:[…]}`，每筆只含 id、canonicalId、favorite、quantity、condition、finish、note）。匯入嚴格驗證：檔案 ≤1 MB、≤2,000 筆、`app`／`version` 必須相符、id 為 ≤128 字的字串且無控制字元、張數為 0–999 的整數、品況在清單內、版本 ≤60 字且只含英數與 `._-`、備註 ≤200 字（控制字元換成空白）；整檔結構錯誤就整個拒絕，單筆不合格則略過並回報筆數。合併不重複：同一張卡取較大的張數、保留星號、已有的文字欄位優先（重複匯入不會把張數加倍）。匯入檔內的圖片網址、名稱等快照一律不採用（避免從檔案載入外部圖片），匯入後依 id 向本站 API 補齊。CSV 匯出沿用並補上品況、版本、備註、作品層 id 欄位，星號收藏（無張數）也列入。
- **界面**：既有 `window.openCollection()` 的原生 `dialog` 擴成清單：圖、名稱、卡號、稀有度、地區、版本徽章、可編輯欄位（含標籤）、查看、移除（先確認），空狀態、匯出／匯入／CSV；觸控目標 ≥44 px。純函式（驗證、合併、搬移、總值）拆在新檔 `collection-store.js`，供測試。

## Consequences

- 清除瀏覽器資料、換裝置、無痕模式都會讓收藏消失；寫入失敗（空間已滿）會在清單內提示並建議先匯出。這是 v0 的已知限制，v1（登入＋雲端）才改善，仍待容量對策（README 第 4.4 節）。
- 參考總值的覆蓋率會偏低（只有 tcgdex-ja 日版、核准清單的官方日版、美版有快照，且只存 ≥0.5 EUR／USD 者），介面一律顯示「N／M 款有參考價」。快照規則（變動 ≥2% 或滿 7 天才寫）使最新一列與當下值的差距通常不超過約 2%，但價格跌破門檻後不再更新，所以要看快照日期。
- 最新一列的取得方式是「抓該批卡的快照列、在伺服器內取每組最新」，沒有 RPC；若日後快照累積到單批超過 5,000 列，需改成 `distinct on` 的 RPC（要 migration，先回滾測試再套用）。
- 移除收藏（含把張數減到 0 且沒有星號）會一併刪除該卡的品況、版本、備註，與原本取消收藏的行為一致。
- v1 登入若做，匯入沿用同一份 JSON 格式與 id 解析規則；本 ADR 不涉及任何帳號、金鑰或付費設定。
